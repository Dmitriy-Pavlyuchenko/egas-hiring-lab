# Hiring Lab

Самостоятельная веб-платформа для тестовых заданий в формате симуляции. В комплекте кейс Новоречинска, кандидатский интерфейс и кабинет организатора.

## Запуск

Требуется Node.js 22.13+ или Docker. В проекте нет npm-зависимостей.

```powershell
npm.cmd start
```

Откройте http://127.0.0.1:3080/organizer. Локальный демонстрационный пароль — `local-demo-change-me`. Создайте приглашение, укажите срок в часах, скопируйте ссылку и откройте её. Путь кандидата можно пройти в любом браузере, которому доступен адрес сервера. Для ссылки, доступной вне вашей машины, разверните приложение по инструкции ниже.

Данные хранятся в `runtime/lab.sqlite`. Путь можно изменить через `DATABASE_PATH`. Переменные можно задать через окружение или скопировать `.env.example` в `.env`.

## Правила

- Срок доступа отсчитывается с выпуска приглашения. Пример: ссылка на 80 часов, созданная в среду в 12:00, истечёт в субботу в 20:00 в том же часовом поясе.
- День симуляции считается отдельно. С момента старта каждый из первых двух дней длится треть первоначального срока приглашения. На третьем дне симуляция остаётся до истечения доступа. Продление меняет дедлайн, сохраняя исходное расписание симуляции. Изменения дня подхватываются при открытии страницы или следующем запросе.
- Новости открываются по дням, а время в карточках — время события в мире кейса. Сообщения и показы прототипа расходуют общий дневной лимит конкретного персонажа. Для предложений и финмодели действуют отдельные лимиты на всю сессию.
- После сдачи работа доступна кандидату для чтения до дедлайна. Истечение или отзыв закрывают кандидатский доступ. История остаётся доступной организатору. Продление истёкшей ссылки отсчитывается от текущего момента, продление активной — от действующего дедлайна.
- Ссылка предоставляет доступ к одной работе и передаётся кандидату как секрет. После сдачи сохраняются время и ссылка. Ссылки на внешние прототипы открывает пользователь в браузере.
- В `case-data/` лежат 13 материалов Новоречинска, полученных через штатное скачивание: пять XLSX, два PDF и шесть Markdown-файлов. Переписки кандидатов и их приглашения хранятся только в базе конкретного развёртывания. Стартовый текст и поля финансовой формы сверены с материалами исходной сессии. Переходы между днями и экран подтверждения сдачи реализованы по доступным данным о сценарии.

## Диалоги

По умолчанию персонажи отвечают по правилам кейса. В этом режиме работает весь пользовательский сценарий, включая принятие и отклонение предложений, письма о намерениях и финансовое согласование. Обратная связь на прототип строится по описанию, а изображения хранятся в истории.

Для свободных диалогов поддерживаются локальный Ollama и собственный HTTP-адаптер. Для Ollama задайте `OLLAMA_MODEL` с именем уже установленной модели и при необходимости `OLLAMA_ORIGIN` (по умолчанию http://127.0.0.1:11434). Для анализа скриншотов нужна модель, принимающая изображения. Используется [Ollama Chat API](https://docs.ollama.com/api/chat).

Для собственного адаптера задайте `CHAT_ADAPTER_URL` и опционально `CHAT_ADAPTER_TOKEN`. Сервер отправляет POST JSON с полями `person`, `kind`, `input`, `history`, `news`. Изображения в текущем показе передаются как `{mime,data}`, где `data` — base64. Ожидаемый ответ — `{"text":"Реплика персонажа"}`. При включённом внешнем адаптере текст и изображения кандидата передаются по этому адресу. Коммерческие предложения и согласования оцениваются серверными правилами и в этом режиме.

## Развёртывание

### Cloudflare Workers

Публичное развёртывание использует Cloudflare Worker и один Durable Object с SQLite. В этой базе сохраняются приглашения, заметки, переписки, результаты и вложения. Развёртывание новой версии сохраняет данные, пока имя Worker и идентификатор Durable Object прежние.

1. В Cloudflare Workers Builds подключите этот репозиторий или используйте `npm install` и `npm run deploy` в авторизованной среде. Wrangler запустит сборку вложений сам. При первом запуске миграция `v1` создаст класс хранилища.
2. В переменной `ADMIN_PASSWORD_SHA256` задайте SHA-256 длинного случайного пароля организатора. Используйте пароль с высокой энтропией, например 32 случайных байта в Base64URL. Пароль и его хеш храните вне Git.
3. Откройте `/organizer` на опубликованном адресе и создайте приглашение. Путь кандидата открывается по уникальной ссылке без учётной записи Cloudflare. `/health` возвращает служебный статус.

Для реплик с внешней моделью можно передать `CHAT_ADAPTER_URL` и, при необходимости, `CHAT_ADAPTER_TOKEN` в переменные Worker. Без интеграции используются правила симуляции.

### Собственный сервер

Запускайте один экземпляр приложения с постоянным томом для SQLite. Используйте `NODE_ENV=production`, отдельный длинный `ADMIN_PASSWORD`, `HOST=0.0.0.0` и `PUBLIC_ORIGIN` с фактическим публичным HTTPS-адресом без завершающего слеша. Настройте TLS на обратном прокси. Пароль храните в секретах окружения. Приглашения будут формироваться на домене, через который открыт кабинет. Локальный демонстрационный пароль в production запрещён.

```text
docker build -t hiring-lab .
docker run --env-file .env -p 127.0.0.1:3080:3080 -v hiring-lab-data:/app/runtime hiring-lab
```

При локальном Docker-запуске укажите `HOST=0.0.0.0` в `.env`. Для резервной копии остановите приложение и сохраните каталог `runtime` целиком либо воспользуйтесь штатной функцией резервного копирования SQLite. Храните резервные копии как закрытые данные.

## Проверка и развитие

```powershell
npm.cmd test
```

Тесты проверяют HTTP-сценарии с управляемыми часами, отдельными кандидатами и отказом провайдера ответов. По умолчанию тесты используют обработчик сервера без сетевого порта. Чтобы пройти тот же набор по реальному HTTP на локальном порту, задайте `LAB_SOCKET_TEST=1`. На Windows значение `pipe` использует HTTP через именованный канал.

Сценарий Новоречинска и материалы находятся в `case.mjs`, правила персонажей — в `dialogue.mjs`. Чтобы добавить кейс, добавьте в массив `cases` запись со своим идентификатором, постановкой, составом собеседников, новостями и материалами. Кабинет покажет новый кейс в списке. При изменении опубликованных материалов сохраните старую запись и добавьте новую с новым идентификатором: выданные приглашения привязаны к первоначальному кейсу. Трёхдневная механика и формы переговоров общие для всех кейсов.


Для сквозного прогона интерфейса запустите отдельный тестовый экземпляр с `DATABASE_PATH=:memory:`, установите Python-пакет `playwright` и браузер командой `python -m playwright install chromium`, затем выполните `python test/browser_e2e.py`. Адрес, демонстрационный пароль и путь к установленному Chromium можно задать через `LAB_TEST_ORIGIN`, `LAB_TEST_ADMIN_PASSWORD` и `CHROMIUM_EXECUTABLE`.
